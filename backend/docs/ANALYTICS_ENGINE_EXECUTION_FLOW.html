Engagement Decay Lifecycle Query (No Starvation)
Decay Algorithm
backend/src/jobs/cron/analyticsCron.job.js:syncAnalyticsMetrics()
Eliminates the legacy take: 200 starvation bug. Instead of always grabbing the newest 200 posts, the query selects posts that are mathematically due for a refresh based on their age:
Lifecycle Tier Post Age Refresh Frequency Rationale
Tier 1: Fresh 0 – 48 Hours Every 2 Hours Highest viral engagement window (likes & comments spike).
Tier 2: Active 3 – 7 Days Every 12 Hours Gradual long-tail reach and shares accumulation.
Tier 3: Mature 8 – 30 Days Every 24 Hours Stable metrics; occasional passive impressions.
Tier 4: Archived 30+ Days On-Demand Only Permanently stops background polling to conserve API quotas.
const eligiblePosts = await prisma.post.findMany({ where: { status: 'PUBLISHED', createdAt: { gte: thirtyDaysAgo }, OR: [ { postAnalytics: { none: {} } }, // Never synced before { createdAt: { gte: twoDaysAgo }, postAnalytics: { some: { lastSyncedAt: { lte: twoHoursAgo } } } }, { createdAt: { gte: sevenDaysAgo, lt: twoDaysAgo }, postAnalytics: { some: { lastSyncedAt: { lte: twelveHoursAgo } } } }, { createdAt: { gte: thirtyDaysAgo, lt: sevenDaysAgo }, postAnalytics: { some: { lastSyncedAt: { lte: twentyFourHoursAgo } } } } ] }, take: 100 // High-performance batch limit per 15-minute tick });

Rate Limiting Detection & Exponential Retry Backoff
Resilience

If Meta responds with HTTP 429 or error code 32 (Page request limit reached), the worker intercepts the status and throws a retryable error. BullMQ automatically reschedules the job with exponential backoff, preventing application quota bans.

Fast Read Path
GET /api/v1/analytics/overview ➔ analyticsLogic.getOverview()
When 100,000 users visit their analytics dashboard, their requests hit Redis first:
  • Cache HIT: JSON returned directly from memory in < 5ms (0 database load).
  • Cache MISS: PostgreSQL runs indexed aggregate scan, populates Redis with 15-minute TTL (900s), and returns.
const cacheKey = `analytics:overview:${userId}:${range}:${platform}`; const cached = await getFromCache(cacheKey); if (cached) return cached; // ⚡ Sub-5ms response! // On Cache Miss: Read DB + Cache for 15 minutes const freshData = await analyticsRepository.getOverviewMetrics(userId, startDate, priorStartDate, platform); await setInCache(cacheKey, freshData, 900); return freshData;
