Engagement Decay Lifecycle Algorithm

How BrandFlow eliminates post starvation, conserves Meta & LinkedIn API quotas, and handles 100,000+ active users with mathematically tiered synchronization.

1. The Core Intuition (Social Media ka Real Behavior)

Social media algorithms do not treat all posts equally over time. Why should our background sync engine?

Tier 1: Viral Window 🔥 High Priority
⏱️ 0 – 48 Hours Old
Every 2 Hours
Post feed me top par hoti hai. Har thodi der me likes, comments aur shares tezi se badhte hain. Frequent sync is essential.
Tier 2: Active Window 📈 Medium
⏱️ 3 – 7 Days Old
Every 12 Hours
Explore & hashtag reach se metrics dheere-dheere accumulate hote hain. Har 2h me call karna Meta quota ka waste hai; 12h me 1 baar kaafi hai.
Tier 3: Mature Window ⏳ Low
⏱️ 8 – 30 Days Old
Every 24 Hours
Engagement almost plateau kar chuki hoti hai. Din me sirf 1 baar sync karke baseline numbers ko accurately lock kiya jaata hai.
Tier 4: Cold Storage 🧊 Archived
⏱️ 30+ Days Old
Auto-Sync Stopped
99.9% engagement freeze ho chuki hoti hai. Background auto-polling permanently band ho jata hai (sirf UI on-demand refresh available).
2. Database ke 2 Magical Columns (The Mathematical Engine)

Poora decision matrix PostgreSQL me in 2 timestamps ke beech ke time-gap par nirbhar karta hai:

Post.createdAt (The Birth Clock 🐣)
Post kab paida hua? Ye decide karta hai ki post kis Tier me fall karta hai (0-48h, 3-7d, ya 8-30d).
Calculates Post Age: (NOW - createdAt)
PostAnalytics.lastSyncedAt (Freshness Speedometer ⏱️)
Aakhri baar Meta/LinkedIn se kab poocha tha? Ye decide karta hai ki post ka cooling-off period poora hua ya nahi.
Calculates Staleness: (NOW - lastSyncedAt)

⏱️ Step 3.1: Dynamic Time Thresholds (6 Math Cut-Offs)
backend/src/jobs/cron/analyticsCron.job.js 
const now = new Date();

// 🕒 Freshness Windows (lastSyncedAt Thresholds)
const twoHoursAgo        = new Date(now.getTime() - 2 * 60 * 60 * 1000);   // 2 ghante pehle ka time
const twelveHoursAgo     = new Date(now.getTime() - 12 * 60 * 60 * 1000);  // 12 ghante pehle ka time
const twentyFourHoursAgo = new Date(now.getTime() - 24 * 60 * 60 * 1000);  // 24 ghante pehle ka time

// 📅 Post Age Boundaries (createdAt Thresholds)
const twoDaysAgo         = new Date(now.getTime() - 48 * 60 * 60 * 1000);  // 48h / 2 din boundary
const sevenDaysAgo       = new Date(now.getTime() - 7 * 24 * 60 * 60 * 1000); // 7 din boundary
const thirtyDaysAgo      = new Date(now.getTime() - 30 * 24 * 60 * 60 * 1000); // 30 din boundary (Archive cutoff)
⚡ Step 3.2: The High-Performance Prisma Query (Single Database Pass)
Prisma Query Execution 
const eligiblePosts = await prisma.post.findMany({
  where: {
    status: 'PUBLISHED',
    
    // 🛑 Cut-Off: 30 din se purane posts database scan se hi bahar nikal gaye!
    createdAt: { gte: thirtyDaysAgo },
    
    OR: [
      // Case 0: Naya post jo abhi publish hua aur kabhi sync hi nahi hua
      { postAnalytics: { none: {} } },
      
      // Tier 1: Fresh (Age 0 - 48 hours) ➔ Sync sirf tab karo agar aakhri sync 2 ghante se purana ho
      {
        createdAt: { gte: twoDaysAgo },
        postAnalytics: { some: { lastSyncedAt: { lte: twoHoursAgo } } },
      },
      
      // Tier 2: Active (Age 3 - 7 days) ➔ Sync sirf tab karo agar aakhri sync 12 ghante se purana ho
      {
        createdAt: { gte: sevenDaysAgo, lt: twoDaysAgo },
        postAnalytics: { some: { lastSyncedAt: { lte: twelveHoursAgo } } },
      },

      // Tier 3: Mature (Age 8 - 30 days) ➔ Sync sirf tab karo agar aakhri sync 24 ghante se purana ho
      {
        createdAt: { gte: thirtyDaysAgo, lt: sevenDaysAgo },
        postAnalytics: { some: { lastSyncedAt: { lte: twentyFourHoursAgo } } },
      },
    ],
  },
  include: { scheduledPost: true },
  take: 100, // 📦 Controlled batch: BullMQ queue me 100 jobs safely push hote hain
});
